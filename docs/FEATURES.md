# Athena-sky 功能規格與對照表（Feature Parity Matrix）

本文件列出 Sky-Drones Cloud 的每一項公開功能，以及 Athena-sky 對應的實作位置與驗證方式。

## 資料來源與限制

| 來源 | 狀態 |
|---|---|
| https://sky-drones.com/sky-drones-cloud（行銷頁） | 受 Cloudflare 機器人驗證保護，自動化工具無法讀取，因此**未**直接引用。 |
| https://docs.sky-drones.com/flight-operations/cloud 及其 10 個子頁（官方文件） | ✅ 主要依據。行銷頁的段落標題（Dashboard、Drones and Operators、Flight Locations、Fleet Management、Flight Logs、3D Mission Planning、Integrated UTM、Real-Time Flights、API）與此文件一一對應。 |

| https://cloud.sky-drones.com/api/v2/ | ✅ 公開 API 根路徑回傳 `organisations` 資源 → Athena-sky API 採相同的 `/api/v2/organisations/` 階層。 |
| 網路搜尋摘要（Unmanned Systems Technology、Cesium 部落格引用的官方文字） | 補充：資料「端對端加密」、日誌「永久保存」。 |

第三方商業服務（Altitude Angel／AirMap／High Lander UTM、DroneLogbook）需要各自的商業帳號與 API 金鑰，本專案無法取得，因此**沒有**內建這些服務的專屬串接。Athena-sky 的做法如下：

* **空域資料**：伺服器定義 `AirspaceProvider` 介面（`apps/server/src/airspace/providers.ts`），內建兩種實作：組織自行繪製或匯入的區域（`OrgZoneProvider`，可編輯），以及營運者設定的外部 GeoJSON 空域來源（`GeoJsonFeedProvider`，環境變數 `ATHENA_AIRSPACE_FEEDS`，例如主管機關公布的無人機限航區；唯讀、定期更新、下載失敗時沿用上一份資料）。空域檢查、飛行授權、任務檢查與飛行後合規都透過同一個 `AirspaceService` 合併所有來源。要串接 Altitude Angel 等商業服務，需另外實作一個 `AirspaceProvider`（本專案未提供）。
* **即時飛行授權與公開安全地圖**：由 Athena-sky 自己的授權流程與安全地圖提供，不會轉送給第三方 UTM。
* **日誌簿匯出**：`LogbookProvider` 介面（`apps/server/src/integrations/logbook-providers.ts`），內建兩種通用格式：JSON 飛行紀錄，以及 multipart CSV 日誌檔上傳。DroneLogbook 沒有公開的匯入 API 文件，所以沒有 DroneLogbook 專屬格式；可指向接受上述格式的端點，或新增一個 provider。

## 功能對照

圖例：✅ 已實作並有自動化測試　◐ 已實作，需外部服務或硬體才能完整驗證

### F1 帳號：註冊與登入（`cloud/sign-up-and-log-in`）
| 需求 | Athena-sky 實作 |
|---|---|
| F1.1 網頁註冊新帳號 | `POST /api/v2/auth/signup`；註冊時自動建立個人組織（owner）。頁面 `/signup`。有設定 SMTP 時（`ATHENA_SIGNUP_CONFIRM_EMAIL`，預設跟著 SMTP 開啟）要先確認 e-mail：回應 202 並寄出確認信，點連結（`/signup/confirm`、`POST /auth/signup/confirm`，24 小時內、只能用一次）並輸入註冊時設的密碼，才建立帳號並登入：連結證明信箱，密碼證明是誰申請的，所以別人先用你的 e-mail 註冊時，你點到他那封信的連結也不會建立他的帳號；每次註冊各有自己的連結與資料（同一信箱最多保留最新 5 筆），任一筆確認後其他的失效（同時確認兩次，例如連點兩下或兩個連結，只會建立一個帳號，另一次回應 409「請直接登入」）；已註冊的 e-mail 得到相同回應，帳號擁有者會收到說明信，所以不會洩漏哪些 e-mail 已註冊。受邀者的 e-mail 已由邀請信確認，直接建立帳號；開啟 e-mail 確認時，邀請連結只寄到受邀者信箱，不會回傳給邀請人（否則邀請人可以替不屬於自己的 e-mail 建立帳號）。忘記密碼的請求不論帳號是否存在都立即得到相同回應，查詢與寄信在回應之後才進行，所以回應時間或郵件伺服器錯誤都不會透露帳號是否存在 |
| F1.2 登入／登出 | `POST /api/v2/auth/login`、`/logout`；httpOnly Session Cookie + CSRF 雙重提交 |
| F1.3 忘記密碼（官方登入頁的 password reset 連結） | `/auth/password/reset` → 郵件（SMTP 或開發用 outbox）→ `/auth/password/reset/confirm` |
| F1.4 多人協作（mission manager、pilot 等角色） | 組織成員、邀請（已有帳號的人也需要本人接受邀請才會加入；回應不透露該 e-mail 是否已有帳號；邀請信寄不出去時不保留邀請，回應 502 `mail_failed`，可修好郵件設定後再邀請；SMTP 連線與回應有逾時，不會卡住）、5 種角色權限矩陣 `packages/shared/src/roles.ts`。成員只能管理不高於自己角色的成員，擁有者角色只有擁有者能授予（`canManageMember`、`grantableRoles`，伺服器與「Members & roles」頁面共用）：管理員看到的擁有者那一列只顯示、不能改角色、執照或移除，角色選單不提供 Owner；執照沒存成功時欄位回到原值並顯示原因。觀察員在任務規劃器只看得到檢視工具，不顯示編輯工具 |

### F4 Flight Locations（`cloud/flight-locations`）
| 需求 | 實作 |
|---|---|
| F4.1 地圖顯示機隊在哪裡飛行 | `analytics/locations`：每趟飛行起點與航跡；頁面 `/locations`（Leaflet 地圖）。航跡預覽（最多 100 點）在飛行結束時與飛行一起儲存，地圖不必每次讀取整段樣本（較早的飛行在第一次顯示時建立） |
| F4.2 確認作業合規、符合法規 | 飛行結束時自動合規檢查：禁航／限航區、法定高度上限（組織設定，預設 120 m）、地理圍欄、是否有核准的空域保留、是否闖入其他業者當時已核准保留的空域（公開保留才顯示業者名稱）；地圖以顏色標示違規。「超出授權範圍」只套用在這趟飛行用到的授權：為它所飛任務申請的授權，或在其範圍內起飛的授權（同一台無人機或組織層級皆同）；同一時段在別處的授權與這趟飛行無關。禁航／限航／臨時限制區不得進入；管制區與危險區只在當下有效的核准授權涵蓋該點時才允許，每一個飛行點都檢查，與即時監控相同：長時間飛行也不抽樣（一小時 5 Hz 的紀錄短短 1.6 秒穿過半徑 8 m 的禁區照樣判為違規），相隔不超過 1 秒的兩筆紀錄之間另外每 2 m 檢查一點，快速掠過兩筆紀錄之間的小區域也抓得到（中斷超過 1 秒的地方不補線；兩筆紀錄的距離超過無人機在那段時間能飛的（100 m/s）時是位置跳動——GNSS 錯誤或損壞的日誌——也不補線）；補的點邊檢查邊產生、不保留，再長、再亂的日誌也只用少量記憶體；區域、授權範圍（紀錄點都在範圍內、但兩筆紀錄之間的直線離開範圍，也算違規）、其他業者保留與地理圍欄都一樣。授權與其他業者的保留只在生效期間算數：從核准的那一刻起（開始時間較早的也一樣），到結束或被撤銷為止（核准與撤銷的時間分別記錄）。飛完才核准的授權不會讓先前的飛行變成合規，別人事後核准的保留也不會讓先前的飛行變成違規；飛完才撤銷的授權或保留，對當時的飛行照樣算數。授權範圍也只約束生效期間的飛行點。邊數很多的空域與走廊沿較長的一邊切成至少半個緩衝寬的帶建立索引，每個點只比對所在帶上的邊（結果與逐邊比對相同），離航跡很遠的空域先略過：三小時、2 Hz 的飛行在三個數百邊的大型管制區內約 0.2 秒算完，沿 5000 點、緩衝 200 m 的東西向道路飛三小時約 1 秒。計算分段進行：以時間切段（約 8 毫秒，每檢查 16 個點看一次用了多久），每個點再費工（例如附近有上萬個授權範圍）也一樣，段與段之間把執行緒讓給其他請求；長日誌的讀取、寫入、分析、匯出與刪除也都分段（見 F6.1），再複雜的空域、再長的飛行也不會讓伺服器停頓。地理圍欄以無人機當時實際執行的為準：載著含地理圍欄的任務時，無人機不論是否在飛這個任務都會執行圍欄，所以手動飛出圍欄同樣算違規（飛行紀錄記下每段時間生效的圍欄） |
| F4.3 依時間區間與機隊篩選 | `from`／`to`／`fleetId` |

### F5 Fleet Management（`cloud/fleet-management`）
| 需求 | 實作 |
|---|---|
| F5.1 追蹤公司所有資產 | 機隊（fleets）與無人機 CRUD，序號、型號、備註。任務經理可以把無人機移到其他機隊（無人機頁的「Move to fleet」），但不能修改無人機的其他設定。刪除無人機會一併刪除它的飛行紀錄、日誌檔與酬載影像，刪除組織則刪除組織所有資料與檔案（含韌體檔）；無人機飛行中、飛行紀錄尚未結束時不能刪除該無人機或其組織（409 `drone_in_flight`／`drones_in_flight`） |
| F5.2 透過 LTE 與無人機即時同步資料 | Athena Link WebSocket（`/api/v2/link`），無人機以裝置金鑰連線，即時遙測 |
| F5.3 查看機上安裝的軟體版本並遠端更新 | `hello` 回報韌體版本；韌體套件上傳（`/firmware`）→ 推送 OTA → 下載、SHA-256 驗證、安裝進度回報 → 版本自動更新 |
| F5.4 看到現在哪些無人機／飛手在線上 | `GET /organisations/:id/online` 及 Live 推播的 `users` 名單 |
| F5.5 單一畫面呈現全機隊狀態：去過哪裡、下一個任務、將遭遇的地形 | 機隊地圖（最後位置與航跡）、下一個排程任務、任務沿線地形剖面（地形最低／最高、最小離地淨空） |
| F5.6 飛行時數、電池壽命、即時飛行／飛行日誌 | 每台累計飛行時數、電池循環次數與健康度估計、連到即時畫面與日誌 |
| F5.7 維修排程（整合協作：maintenance schedules） | 頁面 `/maintenance`：每台無人機的保養工作，依飛行時數、飛行次數、天數任一先到為準；用掉 90% 以上標示「即將到期」，超過為「逾期」；可指派負責人（負責人與具「管理無人機」權限的角色——擁有者、管理員——可標記完成，完成後重新計算週期；只改備註或負責人不會重送到期通知）；維修紀錄（排程保養與臨時維修）；一鍵加入預設保養計畫。伺服器啟動後、每小時與每趟飛行結束時檢查，狀態改變時發出一次通知（通知中心＋即時推播）。維修頁的機隊總飛行時數由飛行紀錄直接加總（不是各機四捨五入後再相加），與儀表板一致 |
| F5.8 預測性維修（predictive maintenance） | 以每趟飛行分析指標（振動、馬達輸出不平衡、每顆電芯電壓驟降、耗電率、健康分數）對累計飛行時數做線性趨勢，預測距離維修門檻還有幾小時：已超過或 10 小時內為「需處理」、50 小時內為「注意」。為避免誤報，趨勢必須顯著（斜率 t 值 ≥ 2.5），且只往後外推資料涵蓋時數的 2 倍（一小時的資料不會被拿來預測幾十小時後）；需處理時通知一次，並附處理建議。正常的指標也說明趨勢：朝門檻移動（約剩幾小時）、朝門檻但太遠無法預測、尚無明確趨勢（附 R²），或遠離門檻。無人機頁與 Dashboard 也顯示維修狀態 |

### F6 Flight Logs（`cloud/flight-logs`）
| 需求 | 實作 |
|---|---|

| F6.3 歷史、進行中、未來作業的完整紀錄 | 飛行列表（完成／進行中）＋任務排程（未來）。上傳或飛行只對應到計畫時間在前後 12 小時內的排程（同一台無人機、同一個任務），提早幾天飛同一個任務不會吃掉之後的排程；已上傳的排程若被別的任務取代，會回到「已排程」。先起飛、在空中才開始的任務（主控台的起飛後再續飛）也會對應到它的排程。任務要飛到最後（或飛到交給返航／降落的最後一項）並降落，排程才標為「已完成」；中途返航時任務仍載在無人機上，排程回到「已上傳」，下一趟飛這個任務會接續同一個排程。排程的飛手必須是能操控無人機的成員（擁有者、管理員、飛手）。無人機重新連線時回報機上沒有這個任務（例如無人機重開機），已上傳的排程回到「已排程」。刪除任務時，還沒飛的排程一併刪除，已飛過的排程保留在紀錄中（顯示當時的任務名稱）；飛行也保留它飛的計畫，規劃航線與航線分析不受影響 |
| F6.4 持續監控全機隊與個別機／飛手 | 儀表板警示、無人機健康趨勢、Webhook `alert.raised` |
| F6.5 DroneLogbook 整合（匯出日誌給合作夥伴） | ◐ 日誌簿匯出連接器（`LogbookProvider`：JSON 紀錄或 multipart CSV 上傳；端點 URL＋加密儲存的 API 金鑰；手動或自動匯出）。飛行頁的「匯出到日誌簿」只在整合已啟用時出現（`GET /integrations/logbook/status`，所有成員可查，不含設定）。無 DroneLogbook 專屬格式（其 API 未公開）；送出的軌跡最多 10,000 點（長時間飛行平均抽點）；另提供 CSV／KML／GPX／JSON 匯出 |
| F6.6 日誌繪圖與匯出（GCS「Logs Analysis」：選欄位繪圖、匯出圖片／KML／CSV） | ULog 主題／欄位瀏覽與任意欄位繪圖、PNG 圖片匯出、KML／CSV／GPX 匯出。ULog 分段讀取，結果保留 10 分鐘（最多 16 個檔案的主題清單、4 條欄位序列），連續繪製不同欄位不必每次重讀整個檔案；匯出一頁一頁串流輸出，飛行再長也不會讓伺服器停頓 |
| F6.7 航線偏差分析（route deviation） | 任務飛行比對「起飛時上傳給無人機的那份計畫」（快照，之後修改任務不影響）與實際航跡。航線從無人機實際起飛的位置算起（飛控在自己的位置起飛，不管計畫畫在哪裡的起降點）；在空中才開始的任務，從開始任務的位置與時間算起，之前的手動飛行不比對。比對項目：橫向偏差的平均、95 百分位與最大值、超出 10 m 走廊的時間比例、規劃航線完成比例（沿航線單向比對，來回重疊的航線也能正確對應到返程）、航段中的最大高度偏差（從離開航線起點到抵達航線終點：不計在起點的爬升——含任務開始前手動起飛的爬升——與抵達終點後的懸停和下降；持續到航線結束、或從航線一開始就存在的高度誤差照樣計入；原地爬升或下降的垂直航段以其高度範圍比對，前後航段各自用到達與離開時的高度）；自動返航不列入比對——任務最後的返航（RTL）航段，以及無人機處於返航或降落模式的所有時段（含故障保護返航，之後未飛的航段算未完成）；偏離時間超過 15%、完成度低於 80%，或高度偏差超過 10 m 時列為發現。飛行頁地圖疊上規劃航線（虛線）與最大偏差點 |
| F6.8 自訂合規與績效報表匯出 | 頁面 `/reports`、`GET /reports/flights`：可依期間、機隊、無人機、飛手篩選，並選擇段落——摘要、績效（依無人機／飛手：時數、距離、平均健康分數、耗電率、航線偏差、發現數）、合規（無問題飛行比例、法規問題類型、飛行中的 UTM 警示、在保養逾期時起飛的飛行）、維修、AI 偵測、飛行清單。輸出 JSON、CSV（文字欄位防試算表公式注入）或可列印 HTML（全部跳脫、CSP `default-src 'none'`，可直接列印成 PDF） |

### F8 Integrated UTM（`cloud/integrated-utm`）
| 需求 | 實作 |
|---|---|
| F8.1 整合 UTM 服務（Altitude Angel、AirMap、High Lander） | ◐ `AirspaceProvider` 介面：組織區域＋外部 GeoJSON 空域來源（`ATHENA_AIRSPACE_FEEDS`），`GET /api/v2/airspace/providers` 顯示各來源狀態（網址只顯示通訊協定與主機，不顯示可能含金鑰的路徑與查詢字串）。未內建商業 UTM 的專屬串接。GeoJSON 支援 Polygon（取外圈，洞會一併涵蓋）、MultiPolygon（每個多邊形一個區域）、LineString（`bufferM`）、Point（`radiusM`），匯入結果列出略過與簡化的每一個項目及原因（網頁在匯入欄下方列出全部，不只前幾個）；外部來源同樣在 `GET /api/v2/airspace/providers` 的 `issues` 列出（略過與簡化分開計數，各最多 40 筆，大量略過不會蓋掉簡化的說明；伺服器紀錄則寫下每一筆原因（每種最多 1000 筆）），「Airspace data sources」表可展開原因。上下限寫反時取兩者之間並提出說明；高度接受公尺數字或帶單位的文字（`m`、`ft`）、`SFC`／`GND`（地面）、`UNL`（無上限）與飛航空層（`FL100`，換算成公尺並說明），其他寫法提出說明並用預設值；生效時間只接受 ISO 8601（日期，或帶時區的日期時間，時區可寫 `Z`、`+08`、`+0800` 或 `+08:00`，不會依伺服器的時區解讀），結束早於開始的項目略過並說明原因，無法解讀的時間提出說明；名稱只有看不見的字元或不是文字時用「Zone N」；類型不分大小寫，也接受常見縮寫（CTR、TMA、TFR 等），不認得的類型會說明並用預設類型；高度限制在 −500 m 到 20000 m（超出時說明；整個在地面以下、上限不高於 0 m 的區域略過，例如只寫了上限 −10 m）；不存在的日期（2 月 30 日）不會被順延成別的日期；半徑與緩衝也接受帶單位的文字（`m`、`km`、`ft`、`NM`（海里）、`mi`），看不懂時略過並說明；閉合的環只有兩個不同角點（[A,B,A]）或角點都在一直線上（面積為 0）的多邊形略過並說明（手動建立時 400）；名稱最長 120 個字，不會把表情符號或組合字切成兩半；線狀區域的緩衝至少 1 m（0 m 的線不涵蓋任何東西，匯入時略過、手動建立時 400）；手動建立或修改區域時生效時間也必須先開始後結束（否則 400）（格式見 README「GeoJSON 空域」） |

| F8.3 天氣資訊 | `GET /api/v2/weather`（Open-Meteo），含風速、陣風、降水、能見度與可飛判定（go／caution／no-go） |
| F8.4 空域資料（區域詳細資訊） | 空域區（禁航、限航、管制、危險、臨時）CRUD；`POST /airspace/check` 回傳衝突與建議；`POST /missions/:id/airspace-check`（可帶 `droneId`）檢查整條任務走廊。大量空域（例如外部來源的數千個區域）：每個區域的外框、生效時段與距離計算只準備一次並保留，組織自己的區域讀取一次後保留 60 秒（新增、匯入、修改、刪除時立即更新）；任務檢查、空域檢查、授權申請、任務開始的檢查、即時監控與飛行後合規都先以外框略過遠處的區域（5000 個 100 邊的多邊形：任務檢查與空域檢查各不到 0.5 秒，即時監控每台每次不到 50 毫秒） |
| F8.5 即時飛行申請與授權，保留空域 | 授權申請（開始時間最早是現在，容許 5 分鐘誤差；不能補申請已經開始的時段。核准與撤銷的時間分別記錄，飛行後的合規檢查依此判斷當時是否有效）→ 自動衝突檢查（空域區、既有保留、時間、高度）→ 自動核准、駁回或待人工審核；經理可人工決議。其他業者的保留為阻擋；組織自己的保留是許可（同一台或未指定機體），保留給同組織另一台無人機時改為待審核——授權申請、`/airspace/check`、任務檢查與核准時的重新檢查都用同一套規則（核准時也重新檢查空域區：申請後才公告的臨時限制區會擋下核准）；非公開的保留不揭露業者名稱、編號或識別碼。取消授權會立即更新即時監控；申請人可取消自己的申請，任務經理以上可取消任何申請（介面只對這些人顯示「取消」）。時段已經結束的申請不能再核准（409，只能駁回：核准了也從未生效）；取消時保留原本的核准者、核准時間與理由，另外記錄取消者與取消時間（之前取消時覆寫掉的決議由遷移移回取消欄位）；航空區頁面的授權列表顯示核准與取消的時間及人員 |
| F8.6 保留空域公開顯示在安全地圖上 | 公開頁 `/safety-map` 與 `GET /api/v2/public/safety-map`（免登入） |
| F8.7 Cylinder（圓柱）與 Corridor（走廊）飛行計畫 | 兩種幾何皆支援，可由任務航線自動產生走廊 |
| F8.8 即時空域監控與通知 | UTM 監控器（`apps/server/src/airspace/utm-monitor.ts`）：空中無人機每 2 秒比對所有空域來源——禁航／限航／臨時限制：接近 150 m 警告、進入為嚴重；管制／危險區：無核准授權覆蓋時警告（只認同一台無人機的授權或未指定機體的組織授權，與飛行後合規檢查相同；未指定機體的組織授權只約束在其範圍內起飛的飛行，遠處的組織授權不會讓其他飛行被判為「超出授權範圍」）；電線／障礙物 50 m 內警告；組織高度上限；自家機隊間隔（水平 20 m／垂直 10 m，同一群飛作業 5 m／3 m；每筆遙測都檢查，並沿著兩筆遙測之間飛過的路段內插比對，兩台在更新之間擦身而過也會發出警報；遙測中斷超過 3 秒的路段不內插）；有人機交通（ADS-B）與無人機故障；進入其他業者已核准保留的空域為嚴重（公開保留才顯示業者與編號）。產生的通知持久化、即時推播到主控台與頂部通知中心（未讀數、全部已讀），並送出 Webhook `utm.alert`；狀況結束（離開空域等）自動標示「結束」 |

### F9 Real-Time Flights（`cloud/real-time-flights`）
| 需求 | 實作 |
|---|---|
| F9.1 透過 LTE 即時控制與影像串流，全網頁、免安裝 | Athena Live WebSocket（`/api/v2/live`）＋瀏覽器頁面 `/live`。模擬無人機的相機拍到的是牠所在的真實地點：伺服器的衛星影像圖磚快取（`ATHENA_IMAGERY_URL`，預設 Esri World Imagery，`GET /api/v2/tiles/imagery/{z}/{x}/{y}`）提供影像，相機依位置、高度、航向與雲台俯角，把影像投影到地面算出畫面，依每列像素的地面涵蓋範圍挑選縮放層級（做法參考 SkyWeave：地理資料由伺服器代理並快取）；離線或停用時退回程式化地景。雲台在空中朝下 45°，降落後回到接近水平，看得到周遭環境。衛星影像與地形的圖磚快取都有容量上限（`ATHENA_IMAGERY_CACHE_MB`、`ATHENA_TERRAIN_CACHE_MB`，超過時先刪最久沒用到的圖磚），每位使用者每小時能讓伺服器向外部服務抓的圖磚數也有上限（`ATHENA_TILE_FETCHES_PER_HOUR`，已快取的不算；地形的高程查詢、模擬與最佳化同樣計入），伺服器不會變成無限制的圖磚代理 |
| F9.2 選擇線上載具並飛行 | 線上無人機清單；指令：解鎖／上鎖、起飛、降落、返航、懸停、飛往點擊位置、模式、速度、任務開始／暫停／續飛、拍照 |
| F9.3 超低延遲 | 端到端 ping（瀏覽器→雲→無人機）RTT 顯示；影像背壓丟幀，確保延遲不累積 |
| F9.4 HD 影像搭配主要遙測 | 二進位 JPEG 影格中繼（SD 640×360／HD 1280×720）；HUD：姿態儀、高度、速度、航向、電池、GPS、連線品質、模式 |
| F9.5 單一頁面操作多台無人機 | 多機格狀檢視，每台各自影像、遙測與控制；只能觀看的角色（觀察員、任務經理）沒有指令欄，影像使用整個寬度。窄的影像欄裡機名單獨占第一列（狀態標籤移到下一列），不會被截斷；3D 檢視的開場鏡頭把整個機隊放在工具列、影像欄與事件紀錄之外的可視區中央 |
| F9.6 手動控制（SmartLink 以 USB 搖桿／遊戲手把手動控制） | 鍵盤與 Gamepad API 手動控制，含控制權鎖定（一機一控制者，其他人觀看） |
| F9.7 群組指令 | 主控台「Swarm」面板：勾選多台無人機，同時送出起飛（可設高度階梯）、懸停、返航、降落（按鈕是「Take off／Hold／RTL／Land selected」：每台各自執行，返航用各自的 RTL 高度；要分層返航請用群飛作業的「Return all」） |
| F9.9 AI 物件偵測（人、車輛）、辨識、追蹤與跟隨 | 開關 AI 需要飛手權限（關閉會結束跟隨）。雲端在即時影像上執行內建偵測器（CenterNet 架構的小型卷積網路，`apps/server/src/vision/athena-detector.json`，109 KB），在 worker thread 中每台每秒 3 幀，不阻塞即時通道；多目標追蹤（地面位置關聯，不受鏡頭移動影響）、類別投票與顏色辨識（人看上衣、車看車身）；由相機模型（位置、高度、航向、雲台俯角、視角）把物體觸地點投影到地面得到經緯度與速度；主控台影像疊框、點選物體即可「Follow」：無人機保持設定高度與距離、鏡頭朝向目標，目標被遮住會重新鎖定，消失 8 秒後懸停。已確認的物體寫入事件與飛行紀錄。具機上 AI 的無人機可改傳 `detections` 訊息（同一套追蹤、定位與跟隨）。有機上 AI 的無人機（`hello` 宣告 `capabilities.ai`）由雲端以 `ai` 訊息開關，偵測在機上進行、以 `detections` 回報，雲端不分析影像，追蹤、定位與跟隨照常；關閉後收到的回報不會讓 AI 再開啟。顯示真實影像的模擬無人機就是這樣運作：內建偵測器是用模擬器的程式化地景訓練的，用在真實影像上誤判很多（實測 60 張畫面誤判 1412 次），所以模擬無人機回報相機視野內的模擬人、車 |
| F9.8 群飛（drone swarm）：同步起飛、航點、降落，並顯示各機遙測 | 編隊飛行（橫隊、縱隊、梯隊、V 字、方陣；轉角斜接，各機航段與領隊平行）或分割航線（依航線長度切割、切點內插，速度與相機觸發狀態延續到下一段）；依距離最佳指派槽位；預覽各機航線、時程與規劃最近間距（不足 10 m 需確認）。執行時同一時刻送出任務開始（同步起飛），每個同步點以「屏障」同步——先到者懸停、最後一台到達後一起出發，航段速度預先配速；最後一點自行盤旋等待，全部到齊後一起返航：返航航段由規劃器明確產生——先在原地爬升到各自的返航高度（高於所有任務高度、彼此相差 10 m）並盤旋等待，全部到達返航高度後才一起飛回，到了起飛點上空再等全部到齊才一起下降降落（這兩處也是同步點）。所以水平飛行時每台都在自己的高度，交錯的回程一律有垂直間隔，不會有已在返航的飛越還在爬升的，也不會有下降穿過還在返航的；預覽的間距檢查與實際飛行一致（不同步返航時間距不足會建議改成一起返航，返航高度因高度上限而小於 10 m 時會建議降低任務高度）。「Return all」（全部返航）也一樣分層：每台先在原地爬升或下降到自己的返航高度，全部到達後一起飛回各自起飛點上空，全部到齊後一起降落；返航途中可以「Land all」原地降落。返航高度依各機自己的任務高度排序（飛得較高的返航也較高），一起在原地爬升時不會穿過上方同伴的高度；返航高度同時受組織高度上限與任務地理圍欄的高度上限限制，最高的返航高度也比上限低 5 m（爬升會稍微衝過頭，貼著上限會觸發地理圍欄保護或高度警報）；空間不夠時預覽會警告。預覽先驗證各機任務（上傳會拒絕的問題直接列為錯誤，上傳按鈕停用），間距不足的建議依接近發生的位置給出：起飛點太近（起降時）、要一起返航、返航高度空間不足、或加大間距與高度階梯。作業進行中，成員自己的「開始任務」「續飛」與切到 MISSION 模式會被拒絕（409，請用作業的控制鈕），主控台上這些按鈕也停用；其他飛行指令（懸停、返航、降落、飛往等）照送，伺服器與無人機接受後該機才退出作業（被拒絕的指令，例如格式不對的模式或空中再起飛，不會讓它退出），其他機不再等它、作業也不再指揮它；拍照不算飛行指令，也不會拿走控制權。按「End」結束作業、或成員退出作業（包括連線中斷又重新連上：在斷線期間已經飛到等待點、停在那裡等的，連線恢復後依它回報的任務進度放行）時，它們之後經過的作業等待點會自動放行，各自飛完任務（不再互相等待），不會停在等待點上空不動；要分層返航請用「Return all」。「Return all」途中按「End」，還在返航的每台改用自己的返航（RTL）飛回起飛點降落，確認視窗也這樣說明；上傳任務期間按「End」，作業即結束，上傳完成後不會再變成「就緒」而卡住群飛面板。返航高度不超過組織的法定高度上限（空間不足時縮小間隔），任何一台超過上限時預覽會警告。飛手接手、斷線或故障保護模式時該機自動退出，其他機不再等待；作業進行中不能用一般上傳替換成員的任務；暫停／續飛／全部返航／全部降落／結束。每台的影像、遙測與群飛狀態（槽位、同步點進度、等待中）同時顯示 |

## 使用者介面

* 設計系統（`apps/web/src/styles.css`）：深色與淺色主題（右上角切換），色彩、間距、圓角、陰影皆為 CSS 變數；側欄與頂列固定為深色；字型 Inter（自行託管，不連外部 CDN）；圖示一律使用 lucide-react（向量圖示，取代文字符號）。
* 外框：可收合的側欄（概覽／作業／資產與資料／組織），頂列有組織切換、角色、連線狀態、即時畫面捷徑、通知中心、主題切換與帳號選單（個人資料、設定、登出）。
* 登入頁：左側產品介紹、右側表單；窄螢幕只顯示表單。
* 以地圖為主的即時主控台與任務規劃器：地圖全版，深色半透明面板（工具列、影像堆疊、事件紀錄、重新定位、群飛、規劃側欄）浮在地圖上；淺色主題下這些面板仍維持深色，以保持在地圖上的可讀性。
* 地圖：深色主題下 OpenStreetMap 圖磚以濾鏡轉為深色（衛星影像不變），圖磚載入前的底色與主題一致。
* 頂列在任何寬度都不會超出畫面：組織選單與狀態膠囊會縮短（過長的組織名稱以省略號結尾），1100 px 以下角色標籤移到帳號選單、使用者名稱縮短，900 px 以下只顯示狀態燈號與頭像。通知未讀數的徽章固定在鈴鐺右上角往外長，兩位數或「99+」也不會蓋住鈴鐺。
* 窄螢幕：900 px 以下側欄改為從頂列「選單」按鈕開啟的抽屜（關閉時不在 Tab 鍵順序裡；打開時焦點移到選單內，Tab 只在選單內循環、背後的頁面不能操作；Esc 或點背景關閉並把焦點還給選單按鈕，點選連結後焦點移到新頁面的標題，點目前頁面的連結也會關閉抽屜；桌面版收合側欄的設定不影響手機上開啟抽屜），雙欄頁面改為單欄；640 px 以下頂列精簡為圖示，通知中心改為全寬，頁面不會出現水平捲動；即時主控台依主控台本身的寬度（不受側欄展開影響）決定工具列樣式：放不下一列文字標籤（含軟體 3D 警示與群飛狀態）時改為只顯示圖示的單列，很窄的手機上圖示可換到第二列而不會超出畫面，下拉選單顯示在影像欄之上，而且一律在主控台底邊之內結束，項目多時在選單內捲動（例如幾十台無人機的「Vehicles」清單與「Online now」）；一次只開一個選單，Esc 或點選單外面會關閉；手機上的側面板停在事件紀錄上方；面板與地圖控制項一律放在工具列下方；窄主控台的影像欄自動縮窄。寬表格在自己的框內左右捲動，手機上影像改為下方橫向捲動列，事件紀錄預設收合；重新定位、群飛與詳情面板一次只開一個。
* 3D 主控台與規劃器會自動避開重疊的標籤（無人機標籤依實際螢幕矩形往上錯開，互不重疊；被無人機標籤蓋住的航點編號暫時隱藏；規劃器航點標籤重疊時保留選取中的航點與較前面的航點）。無人機標籤也會避開主控台的工具列、影像欄、事件紀錄與地圖切換面板：上方沒有空間時放到無人機下方，最多離開無人機四層標籤的距離，仍放不下就暫時隱藏（選取中的無人機優先）；被推開的標籤有一條指示線連回自己的無人機。手機上機隊擠在一起時也不會有名稱被面板蓋住。過長的機名在 3D 標籤上縮短為 20 個字元並以省略號結尾（完整名稱在影像欄與清單中）。
* 手機與平板上規劃器的面板是底部抽屜，地圖的資料來源署名（Data attribution）移到抽屜上方，仍點得到。規劃器的「Resume」對話框：勾選立即開始時按鈕是「Resume now」，否則是「Upload for later」：之後在主控台開始——在地面上用影像格的開始鍵（▶，會先確認，解鎖並起飛）或詳情的「Start mission」，在空中用 Resume。
* 地圖影像：瀏覽器連不到圖磚伺服器（離線網路、防火牆、Proxy）時，3D 主控台、規劃器與飛行重播會顯示「map imagery unavailable」，並說明是哪一台主機連不到，不會只剩一顆空白地球。有 Cesium ion token 時，3D 衛星圖是 Bing Maps（經由 ion），圖磚一律走 HTTPS，所以只有 HTTP 的部署也能顯示。網站對其他網站只送出來源（`Referrer-Policy: strict-origin-when-cross-origin`），符合 OpenStreetMap 圖磚的使用政策。
* 維修工作表在放得下所有欄位時是表格，放不下時（依表格本身的寬度，例如 1280 px 的主從版面或手機）每項工作改成一個區塊，「Done」與編輯、刪除按鈕一律完整可見，不需要左右捲動。
* 頂列的角色標籤在角色被改變時立即更新（伺服器在即時連線上通知）；設定頁的按鈕（建立組織、機隊、權杖、撤銷、Webhook 測試／傳送紀錄／暫停／刪除、撤回邀請）失敗時顯示伺服器的原因，不會毫無反應；設定頁的分頁寫在網址上（`/settings?tab=profile`），帳號選單的「My profile」直接打開個人資料；網址指定的分頁若該角色不能使用（例如飛手打開 `?tab=webhooks`），改開「組織」分頁，Webhook 列表讀取失敗時顯示原因。成員被移出組織時，開著的頁面立即跟著更新：即時連線收到撤銷後重新讀取帳號資料，改顯示其他組織或「不屬於任何組織」，也不再重試連線。
* 名稱（無人機、機隊、任務、空域區、組織、個人、權杖、維修工作與紀錄）前後看不見的字元會去掉（空白，以及零寬空格、連接字元、BOM、韓文填充字元、空白點字、標籤字元、補充變體選擇符等；伺服器、網頁表單與資料庫遷移用同一份清單），只由這些字元組成的名稱一律拒絕（伺服器在驗證前處理，網頁表單也不允許送出；名稱中間的連接字元保留，例如組合表情符號）；先前存成這類名稱的在升級時補上預設名稱。
* 伺服器更新後，還開著舊版頁面的瀏覽器在載入已不存在的舊版程式時，會自動重新整理一次取得新版；如果仍然失敗，頁面顯示「Athena-sky has been updated」與重新整理按鈕，側欄照常可用，不會整頁空白。其他頁面錯誤也一樣顯示說明，不會空白。應用程式頁面（`index.html`）每次都向伺服器確認（`no-cache`），帶雜湊的程式檔永久快取，不存在的檔案回應 404 而不是應用程式頁面。
* 登入後只會導向本站的頁面：`next` 參數若不是站內路徑（例如 `//evil.example`），改回到 Dashboard。
* 影像格標頭：機名太長時先以省略號縮短，狀態標籤（解鎖狀態、飛行模式等）一律完整顯示，放不下的標籤整個隱藏，不會被切掉一半。沒有相機的無人機（`hello` 未宣告 `capabilities.video`）顯示「No camera on this drone」，也不會向它要求影像。
* 3D 規劃器的「Fit mission」、俯視正交與開啟既有任務時的視角，都會把任務放在實際看得到的範圍內（避開上方工具列、桌面版右側面板或手機的下方面板）。規劃器標籤依螢幕矩形擺放：優先在標記上方，否則下方、右側、左側，都會重疊才隱藏（選取中的航點一定顯示）。

## AI 偵測模型的來源與驗證

* 訓練資料：模擬器相機以與即時影像完全相同的流程產生（畫面含 HUD、JPEG 壓縮、相同的縮圖函式），5 個不同世界、4000 張訓練／600 張測試（`tools/vision/make-dataset.ts`）。過小或大部分在畫面外的物體標為「忽略」。
* 訓練：`tools/vision/train_detector.py`，只用 numpy（im2col 卷積、手寫反向傳播、Adam），反向傳播以數值梯度檢查驗證（最大相對誤差 2×10⁻⁷）。
* 保留測試集（600 張，IoU ≥ 0.5）：人 精確率 0.981／召回率 0.953；車輛 0.948／0.910（數值存於模型檔 `meta`，`GET /api/v2/vision/model` 可查）。
* TypeScript 推論與 numpy 的輸出一致性測試（`apps/server/test/vision.test.ts`，誤差 < 2×10⁻³）。
* 未參與訓練的新世界（120 張，10–25 m 高）：人 精確率 1.00／召回率 0.98、地面定位誤差中位數 0.2 m、顏色辨識 93%；車輛 1.00／0.98、1.0 m、90%。
* 限制：內建模型是在模擬器影像上訓練的，用於真實無人機影像時需換成以真實空拍資料訓練的模型（相同檔案格式 `athena-centernet-1`，或由機上 AI 傳送 `detections`）。重新訓練：`npx tsx tools/vision/make-dataset.ts <資料夾>`，再執行 `python tools/vision/train_detector.py <資料夾> apps/server/src/vision/athena-detector.json apps/server/test/fixtures/detector-parity.json`。

## 驗證方式
